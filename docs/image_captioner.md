# `enrich_chunks` — Deep Dive (`image_captioner.py`)

`enrich_chunks` is the multimodal enrichment step that runs **after chunking** and **before embedding**. It takes every non-text chunk (tables, images, formulas, algorithms) and replaces its raw OCR text with a richer, semantically meaningful description generated by GPT-4o. This dramatically improves retrieval quality for non-text content.

---

## Why enrichment is needed

Raw OCR output for a table looks like:
```
Haemoglobin 13.5 g/dL 12–17 Normal
WBC 7200 /µL 4000–11000 Normal
```

That's hard to embed well. After enrichment, the same chunk becomes:
```
This table shows a complete blood count (CBC) report for a patient,
listing test parameters, measured values, reference ranges, and clinical status.
```

The semantic summary embeds much better for retrieval, while the full markdown table is preserved in `chunk.caption` for the generation LLM.

---

## Signature

```python
async def enrich_chunks(
    chunks: list[Chunk],
    pdf_path: Path,
    client: AsyncOpenAI,
    model: str = "gpt-4o",
    max_concurrent: int = 5,
) -> list[Chunk]:
```

| Parameter | Purpose |
|---|---|
| `chunks` | All chunks from `document_aware_chunking` (mixed modalities) |
| `pdf_path` | Source PDF — used to crop image regions for vision calls |
| `client` | Authenticated `AsyncOpenAI` client |
| `model` | GPT-4o by default — needs vision capability |
| `max_concurrent` | Shared semaphore limit across ALL modality calls (default 5) |

Returns the **same list mutated in-place** — `chunk.text` and `chunk.caption` are updated directly.

---

## High-level flow

```
enrich_chunks(chunks, pdf_path, client)
  │
  ├─ for each chunk:
  │     image    → _enrich_image_single()    ← vision call (crop PDF region → base64 → GPT-4o)
  │     table    → _enrich_table_single()    ← text call (JSON mode)
  │     formula  → _enrich_formula_single()  ← text call
  │     algorithm→ _enrich_algorithm_single()← text call
  │     text     → skipped (unchanged)
  │
  └─ asyncio.gather(*tasks)  ← all calls fire concurrently, capped by semaphore
```

---

## Concurrency model (lines 539, 577)

```python
semaphore = asyncio.Semaphore(max_concurrent)
await asyncio.gather(*tasks)
```

All enrichment coroutines are collected into a `tasks` list first, then fired together via `asyncio.gather`. The shared `semaphore` ensures at most `max_concurrent=5` GPT-4o API calls are in-flight at once — prevents rate limit errors on large documents.

Each per-modality helper acquires the semaphore at the start:
```python
async with semaphore:
    response = await client.chat.completions.create(...)
```

## Per-modality enrichment

### Image chunks — `_enrich_image_single` (lines 242–294)

**Step 1 — Crop the PDF region to base64 PNG** (`_crop_chunk_to_base64`):
```python
page_img = pdf_page_to_image(pdf_path, chunk.page - 1, dpi=150)
w, h = page_img.size
# bbox is in normalised 0–1000 coords from PP-DocLayoutV3
x1 = int(bbox[0] * w / 1000)
y1 = int(bbox[1] * h / 1000)
x2 = int(bbox[2] * w / 1000)
y2 = int(bbox[3] * h / 1000)
crop = page_img.crop((x1, y1, x2, y2))
```
If the crop is smaller than 50×50 px, it's skipped (likely detection noise).

**Step 2 — Gather surrounding document context** (`_get_surrounding_context`):
Looks up to 2 chunks before and after, on the same or adjacent page, and extracts their text (max 400 chars each). This gives GPT-4o the document context around the figure — e.g. "Figure 3 shows the patient's trend over 6 months" — so it can write a more accurate caption.

**Step 3 — Vision API call** with the system prompt that classifies into:
`CHART | DIAGRAM | PHOTO | SCREENSHOT | OTHER`

Then asks for structured output:
```
TYPE: CHART
CAPTION: <1-2 sentence semantic description>
DETAIL: <axis labels, data series, key values, main trend>
STRUCTURE: <grouping and containment relationships>
```

**Result stored on chunk:**
```python
chunk.caption = caption        # short 1-2 sentence caption (for generation LLM)
chunk.text = full_text         # full structured response (for embedding)
chunk.image_base64 = b64       # PNG bytes stored for multimodal generation
```

### Table chunks — `_enrich_table_single` (lines 297–374)

Uses **JSON mode** (`response_format={"type": "json_object"}`) to force structured output.

**System prompt asks GPT-4o to:**
1. Count columns and rows
2. Reproduce the **complete** table in markdown (every row, every column, no truncation)
3. Write a 1-2 sentence semantic summary

**Expected JSON response:**
```json
{
  "num_columns": 5,
  "num_rows": 12,
  "markdown_table": "| Test | Result | Unit | Range | Status |\n|---|---|---|---|---|\n| Haemoglobin | 13.5 | g/dL | 12-17 | Normal |\n...",
  "summary": "This table shows a complete blood count report listing haematology parameters with measured values, reference ranges, and clinical interpretation for a patient."
}
```

**Validation step** (`_validate_table_extraction`):
After parsing the JSON, the actual markdown row count is compared against `num_rows`. If they differ by more than 30% (ratio < 0.7 or > 1.5), a **retry** is triggered with an explicit correction prompt:
```
IMPORTANT: A previous extraction reported 12 rows but the markdown output was
incomplete. Please carefully count ALL rows and reproduce the COMPLETE table.
```

**Result stored on chunk:**
```python
chunk.caption = markdown_table   # full table for generation LLM (e.g. used in answer synthesis)
chunk.text = summary             # semantic summary for embedding/retrieval
chunk.image_base64 = b64        # visual crop also stored (for multimodal generation)
```

This split is intentional: **retrieval uses the summary** (more semantically dense), **generation uses the full markdown table** (more factually complete).

---

### Formula chunks — `_enrich_formula_single` (lines 412–455)

Sends raw LaTeX text to GPT-4o with a prompt asking for:
```
SUMMARY: <plain English — what it computes, its domain, where it appears>
DETAIL: <define each symbol, list key properties and use cases>
```

```python
chunk.caption = raw_ocr_text    # original LaTeX preserved as caption
chunk.text = enriched_response  # verbal description for embedding
chunk.image_base64 = b64        # visual crop of the formula region
```

---

### Algorithm chunks — `_enrich_algorithm_single` (lines 458–503)

Same pattern as formula but with an algorithm-specific prompt:
```
SUMMARY: <one paragraph — what it does, purpose, problem it solves>
DETAIL: <inputs/outputs, main steps, time/space complexity, design decisions>
```

Uses the algorithm's own variable names and terminology.

## What does NOT get enriched

```python
elif chunk.modality == "text":
    pass  # skipped — plain text embeds well as-is
```

Text chunks from `document_aware_chunking` already have good semantic content from the OCR pass. Only non-text modalities benefit from the extra GPT-4o call.

---

## After enrichment — what each chunk field holds

| Modality | `chunk.text` (for embedding) | `chunk.caption` (for generation) | `chunk.image_base64` |
|---|---|---|---|
| `text` | original OCR text | `None` | `None` |
| `table` | semantic summary | full markdown table | PDF crop PNG |
| `image` | full structured description | short 1-2 sentence caption | PDF crop PNG |
| `formula` | verbal description | original LaTeX | PDF crop PNG |
| `algorithm` | semantic description | original pseudocode | PDF crop PNG |

## Full pipeline position

```
DocumentParser.parse_file()         ← OCR via Ollama / GLM-OCR
    └─ ParseResult
document_aware_chunking(pages)      ← split into RAG chunks
    └─ list[Chunk]  (raw OCR text)
enrich_chunks(chunks, pdf_path)     ← THIS FILE: replace text with GPT-4o descriptions
    └─ list[Chunk]  (enriched text + captions + base64 images)
embedder.embed(chunks)              ← embed chunk.text into vectors
vector_store.upsert(chunks)         ← store in Qdrant
```
